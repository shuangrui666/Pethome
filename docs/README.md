## 文档编写原则

1. **以实际实现为准**：页面或规划文案存在，不等于功能已经可用。
2. **证据优先**：命令、接口、配置和测试结论应能通过代码、运行结果或测试记录复核。
3. **状态明确**：使用“待核验、编写中、待验证、已验证”等状态，不提前标记完成。
4. **保护隐私**：截图、日志和示例不得包含真实密码、Token、密钥或用户隐私。
5. **同步维护**：代码、接口或部署方式发生变化时，应同步检查相关文档。

## 建设顺序

- 第一阶段：审计现有前后端入口、服务部署和真实功能状态。
- 第二阶段：验证本地开发环境、构建命令、API 与 Socket.IO 配置。
- 第三阶段：根据真实页面编写用户手册，根据已验证工程事实编写开发者手册。
- 第四阶段：补充截图、接口示例、测试记录和部署验收证据。
- 第五阶段：发布前进行文档链接、版本和内容一致性检查。

> 当前文件仅建立文档结构与编写规范，不代表 PetHome 已完成部署验收，也不代表 README 中规划的 AI 功能已经实现。
