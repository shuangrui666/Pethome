# PetHome 新版首页改版设计方案

- **文档类型**：产品与前端设计方案
- **版本**：1.0
- **状态**：设计方案已确认，待现有页面审计与实施
- **适用仓库**：`shuangrui666/Pethome`
- **确认的产品定位**：综合宠物服务平台 + 智能项圈科技产品
- **确认的开发顺序**：先做好完整网站，再逐步强化智能项圈

> 本文定义目标体验、页面信息架构和实施要求。文档中的页面、功能和视觉示例属于设计目标，不代表相关功能已经在当前代码中实现或已经通过测试。

## 1. 产品定位与设计目标

PetHome 是一个面向宠物主人及宠物服务参与者的综合宠物服务平台，并以智能项圈和后续 AI 能力形成差异化。

新版首页需要同时完成两项任务：

1. 让首次访问者快速理解 PetHome 提供哪些宠物服务，以及如何开始使用。
2. 展示智能项圈作为平台科技产品的方向和价值，但不让项圈产品取代综合服务平台的主定位。

品牌主张：

- **英文方向**：Every Pet Deserves a Better Life.
- **中文方向**：让每一只宠物，都拥有更好的生活。
- **辅助表达**：从日常照护、健康管理，到智能定位与社区寻回，让宠物和主人之间的生活更加美好。

设计关键词：高级、现代、温暖、可信赖、专业、有产品感。

## 2. 视觉设计方向

### 2.1 品牌视觉

采用面向消费者的温暖宠物生活方式视觉，与面向智能设备的专业科技产品视觉相结合：

- 宠物服务和社区页面：温暖、亲和、真实、有生活感。
- 智能项圈和数据页面：清晰、专业、克制、有科技感。
- 全站保持一致的字体层级、间距、按钮、卡片、图标和交互规则。

### 2.2 初步色彩建议

| 用途 | 建议色值 | 说明 |
|---|---|---|
| 主色 | `#173D32` | 深森林绿，用于品牌和主要操作 |
| 页面背景 | `#F7F5EF` | 暖白/浅奶油色 |
| 辅助色 | `#B9D7C5` | 柔和薄荷绿 |
| 强调色 | `#E9A66B` | 温暖橙色，少量强调 |
| 正文深色 | `#252B29` | 深灰绿，提高可读性 |

以上为设计起点，正式实施前应检查现有品牌素材、对比度和无障碍要求，再统一成设计 token；不可在各页面随意硬编码颜色。

### 2.3 字体、图片与组件

- 使用清晰、现代、易读的字体层级。
- 优先使用经过授权、可稳定访问的本地字体或可靠字体资源，避免生产构建必须临时访问 Google Fonts 才能成功。
- 图片以真实、高质量宠物摄影为主，避免低质量素材、过度卡通化和风格混杂。
- 卡片采用适度圆角、轻量阴影和充足留白。
- 动效以轻量过渡、悬停反馈和自然滚动为主，避免影响性能和可访问性。
- 统一按钮、表单、导航、空状态、加载状态、错误状态和焦点样式。

## 3. 首页信息架构与内容顺序

首页采用从品牌认知到服务使用，再到科技产品和社区参与的叙事顺序：

1. 顶部导航
2. Hero 品牌主视觉
3. 核心宠物服务
4. PetHome 智能项圈专区
5. 宠物安全与寻回
6. 宠物健康与档案
7. 宠物社区
8. AI 智能能力
9. 品牌价值与信任
10. 页脚

### 3.1 顶部导航

建议导航内容：

- 左侧：PetHome 品牌标识。
- 中间： 首页、宠物服务、智能项圈、寻宠中心、宠物社区。
- 右侧：登录、注册；登录后显示账户入口、消息和个人中心。

交互要求：

- “宠物服务”可展开领养、医疗健康、救助、托管、用品、训练等分类。
- 智能项圈进入独立产品介绍或设备入口。
- 寻宠中心作为重要快捷入口。
- 桌面端使用清晰的固定导航；移动端使用折叠菜单。
- 不把所有子功能塞进一级导航。

### 3.2 Hero 品牌主视觉

**推荐标题**：让每一份陪伴，都更安心。

**推荐说明**：从日常照护、健康管理，到智能定位与社区寻回，PetHome 让宠物和主人之间的生活更加美好。

布局建议：

- 桌面端左右布局：左侧标题、说明和行动按钮；右侧高质量宠物主视觉。
- 背景以暖白为主，使用少量森林绿装饰。
- 主按钮：探索宠物服务。
- 次按钮：了解智能项圈。
- 首屏重点是建立品牌认知，不堆叠全部功能说明。

### 3.3 核心宠物服务

推荐标题：**Everything Your Pet Needs.**

推荐说明：从日常照护到重要时刻，陪伴宠物生活的每一步。

六项服务卡片：

| 服务 | 卡片说明 | 目标入口 |
|---|---|---|
| 宠物领养 | 为等待家的生命寻找新家庭 | 领养列表/详情 |
| 医疗健康 | 记录健康与医疗服务 | 医疗健康服务 |
| 宠物救助 | 让救助信息得到更多关注 | 救助信息 |
| 宠物托管 | 寻找值得信赖的照护服务 | 托管服务 |
| 宠物用品 | 发现日常生活所需好物 | 用品列表 |
| 宠物训练 | 帮助宠物建立良好习惯 | 训练服务 |

每张卡片必须有清晰标题、简短说明和真实可访问的入口；若目标功能尚未实现，应标注规划状态或暂不展示为可用入口。

### 3.4 智能项圈专区

推荐标题：**More Than a Collar. A Smarter Way to Care.**

推荐说明：通过智能项圈与数字化服务，让主人更好地了解宠物的位置、活动和日常变化。

布局建议：左侧产品/佩戴场景图，右侧介绍与入口，下方展示能力模块：

- GPS 定位与历史轨迹
- 智能电子围栏与规则告警
- 活动数据和趋势
- 多宠物管理与家庭共享

行动按钮：探索智能项圈。

功能状态必须真实：未接入设备或数据链路时，只能展示清楚标注的产品概念、交互原型或演示数据，不得伪装成真实实时定位或告警。

### 3.5 宠物安全与寻回专区

推荐标题：**Together, We Bring Them Home.**

内容方向：

- 走失信息发布
- 寻宠信息检索
- 地图与区域筛选
- 社区协助和线索提交
- 走失事件进展更新

行动按钮：进入寻宠中心、发布走失信息。

只展示经过授权、真实发布的信息。项圈电子围栏告警与社区寻宠可以形成产品联动，但不能暗示平台会自动向社区公开宠物位置或个人信息。

### 3.6 宠物健康与档案

推荐标题：**Every Little Detail Matters.**

可展示的内容方向：

- 宠物基本档案
- 医疗、疫苗和护理记录
- 活动历史与趋势
- 已关联设备状态
- 主人需要关注的记录

应明确区分主人录入的医疗记录、设备采集的数据和系统生成的辅助分析。设备温度读数不得直接表述为宠物核心体温或医学诊断。

### 3.7 宠物社区

推荐标题：**A Community That Cares.**

首页只展示精选内容，不复制整个社区信息流。内容方向：

- 宠物日常动态
- 领养与救助故事
- 养宠经验分享
- 寻宠互助信息

展示真实内容时应尊重用户隐私、内容授权和社区治理规则。

### 3.8 AI 智能能力

推荐标题：**Understand More. Care Better.**

未来能力方向：

- 宠物活动模式分析
- 个体长期趋势
- 异常变化提示
- 走失线索辅助匹配

AI 输出属于辅助信息，不替代兽医诊断。AI 不得自行触发按摩、触觉刺激或其他可能影响宠物身体的硬件动作。首页不得把尚未开发或验证的 AI 能力描述成已经可用。

### 3.9 品牌价值与信任

推荐标题：**Care Is More Than a Service.**

三个价值支柱：

- 关爱：让每只宠物得到更好的照护。
- 安全：重视宠物安全、隐私与数据保护。
- 连接：让主人、家庭和社区形成互助关系。

避免使用未经证实的用户数量、成功寻回率、合作机构数量或其他宣传数据。

### 3.10 页脚

建议包含：

- PetHome 品牌介绍
- 宠物服务
- 智能项圈
- 社区与寻宠
- 帮助中心
- 隐私政策与用户协议
- 联系方式和社交媒体

所有链接必须指向真实存在的页面；尚未建立的链接不得伪装为可用。

## 4. 首页视觉权重建议

以下比例表示首页设计注意力的初步分配，不代表页面高度或开发工时：

| 区域 | 建议权重 |
|---|---:|
| Hero 品牌主视觉 | 24% |
| 核心宠物服务 | 20% |
| 智能项圈 | 18% |
| 安全与寻回 | 13% |
| 宠物档案与健康 | 9% |
| 社区与 AI | 11% |
| 品牌与页脚 | 5% |

综合平台的服务入口和品牌主视觉优先；智能项圈应有足够辨识度，但不应取代综合平台定位。

## 5. 交互与响应式要求

| 元素 | 要求 |
|---|---|
| 导航 | 下拉菜单、移动端折叠、明确当前状态 |
| 主按钮 | 清晰主次、悬停/点击/禁用状态完整 |
| 服务卡片 | 有真实入口、键盘可访问、触控区域合理 |
| 产品区域 | 产品图和功能说明形成明确层次 |
| 滚动动效 | 轻量、可减少动态效果，不影响阅读 |
| 加载状态 | 使用骨架屏或明确加载提示 |
| 空状态 | 说明当前无内容并给出合理下一步 |
| 错误状态 | 说明问题并提供可理解的恢复方式 |
| 无障碍 | 语义化结构、键盘操作、图片替代文本、足够对比度 |

响应式要求：

- 桌面端：利用宽屏，保持内容最大宽度和舒适留白。
- 平板端：服务卡片和内容区适当变为两列。
- 手机端：导航折叠、卡片单列、按钮方便触控，避免横向溢出。

## 7. 分阶段实施计划与验收标准

### 阶段 0：现有页面和工程审计

- 盘点实际生效的前端入口和首页路由。
- 盘点现有页面、组件、样式、图片和导航链接。
- 检查首页依赖的认证、API、数据和权限。
- 记录可复用、需修改、需替换和待确认的内容。
- 明确根目录与 `client/` 的关系，避免双重维护。

**验收**：形成有文件路径和证据的页面清单；未审计前不删除旧组件、不覆盖入口、不大规模重构。

### 阶段 1：品牌视觉系统

- 定义色彩、字体、间距、容器宽度和断点。
- 定义导航、按钮、卡片、表单、图标和反馈状态。
- 检查对比度、键盘可访问性和移动端使用。

**验收**：有统一 token 和基础组件规范，主要页面可复用。

### 阶段 2：首页首屏与服务入口

- 实现导航和 Hero。
- 实现六类核心服务入口。
- 核对每个入口的实际路由和功能状态。

**验收**：首屏布局符合设计、导航可用、服务入口不指向虚假页面。

### 阶段 3：智能项圈与安全寻回专区

- 实现产品介绍与能力展示。
- 实现寻宠入口和信息展示区域。
- 对未接入设备的内容明确标记为演示或规划。

**验收**：产品定位清晰；无伪造实时设备数据或未实现告警。

### 阶段 4：健康档案、社区、AI 和品牌内容

- 逐个实现首页内容区。
- 对接已有真实数据或明确的演示状态。
- 检查隐私、授权和医疗/AI 表述边界。

**验收**：页面信息准确，未实现功能不冒充已上线。

### 阶段 5：响应式、质量与部署验收

- 验证桌面、平板和手机布局。
- 验证链接、按钮、加载、空状态和错误状态。
- 执行 lint、生产构建和必要测试。
- 核对部署平台实际使用的配置与构建产物。

**验收**：记录命令、环境、结果和遗留问题；只有实际通过的项目才能标记为已验证。

## 8. 改版保护原则

1. 页面视觉可以大幅重做，但不得因此随意删除已有后端、数据库或认证能力。
2. 改动前先检查 Git 状态并建立可回退的提交或备份。
3. 一次只实施一个可验收的页面/组件任务。
4. 每次修改后检查实际页面和控制台错误，再继续下一项。
5. 不把设计稿、静态原型、演示数据或文档规划称为已上线功能。
6. 不在没有证据的情况下宣称部署成功、接口可用或设备已连接。
7. 不把 AI 分析、电子围栏规则和家庭权限混为一谈；权限必须由后端执行，电子围栏需要可靠的位置数据与规则处理。
